# openpi 教程飞书发布设计

## 目标

将 `docs/tutorial` 中的 15 篇中文 Markdown 教程整理为一套便于阅读、检索和后续更新的飞书云文档，同时保留原有章节顺序、代码示例、表格和课程导航。

## 方案比较

1. **章节式多文档（采用）**：在“我的空间”新建一个文件夹，每个 Markdown 对应一篇飞书文档。优点是单篇长度可控、排障手册和术语表便于独立检索、后续可单章更新；代价是需要重建跨文档链接。
2. **合并为一篇长文档**：导航集中，但约 6,800 行内容会导致加载、定位和维护体验较差。
3. **飞书知识库目录树**：层级和导航体验最好，但需要用户提供目标知识空间或确认创建知识库节点，不适合作为未指定目标位置时的默认落点。

## 飞书目录结构

在当前用户的飞书“我的空间”根目录新建文件夹 `openpi 零基础章节式教程`，文档按以下顺序排列：

1. `00 课程入口`
2. `01 课程大纲`
3. `02 第 01 章：VLA 与机器人学习基础`
4. `03 第 02 章：环境安装与双运行时自检`
5. `04 第 03 章：第一次 LIBERO 推理`
6. `05 第 04 章：openpi 架构与一次请求的数据流`
7. `06 第 05 章：数据协议与 Transform`
8. `07 第 06 章：JAX、NNX 与 π₀ 基础`
9. `08 第 07 章：准备小规模数据集`
10. `09 第 08 章：配置教学微调`
11. `10 第 09 章：运行短程 LoRA`
12. `11 第 10 章：服务与闭环评测`
13. `12 第 11 章：下一步`
14. `13 课程术语表`
15. `14 故障排查手册`

数字前缀仅用于确保飞书文件夹中的稳定排序；正文一级标题保留原教程标题。

## 内容转换规则

- 保留标题层级、段落、列表、表格、引用、代码块和行内代码。
- 教程目录内的相对文档链接替换为对应飞书文档链接；带 Markdown 标题锚点的链接降级为目标文档链接，并在链接文字中保留原章节语义。
- 指向仓库其他文件的相对链接转换为 `https://github.com/Physical-Intelligence/openpi/blob/main/` 下的源码链接。
- 不修改命令、配置名、checkpoint 名、路径、代码示例和技术结论。
- 原目录没有 Markdown 图片，因此无需上传或重建图片资源。

## 发布流程

1. 检查飞书用户身份和云盘权限。
2. 在“我的空间”创建目标文件夹。
3. 创建 15 篇占位文档，获得稳定的飞书文档 URL。
4. 基于 URL 映射生成临时发布稿，转换跨文档链接和仓库源码链接。
5. 将发布稿写入对应飞书文档。
6. 逐篇读取标题和正文摘要，核验文档数量、顺序、关键代码块与链接。
7. 返回文件夹链接和导入结果清单。

临时发布稿只放在 `/tmp`，不改写 `docs/tutorial` 源文件。

## 异常处理

- 若未登录或用户授权缺少 Drive/Docs 权限，发起最小范围授权并等待用户完成后继续。
- 若单篇文档超过接口限制，按二级标题拆分写入同一文档，不改变章节边界。
- 若某篇写入失败，保留已创建文档并只重试失败文档，不重复创建整个目录。
- 若飞书不支持某种 Markdown 表达，优先保留文本和代码语义，再使用飞书原生块结构替代。

## 验收标准

- 目标文件夹中恰好有 15 篇教程文档，标题和顺序符合设计。
- 课程入口、课程大纲、术语表和排障手册可独立打开。
- 每篇正文包含原一级标题，代码块和表格没有明显丢失。
- 教程内部主要导航指向飞书文档，源码引用指向 GitHub 主分支。
- 最终向用户提供可访问的飞书文件夹链接。
